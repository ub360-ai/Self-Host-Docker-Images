# Deploying Harbor on Coolify — Complete Guide

A step-by-step, copy-pasteable walkthrough for running this Harbor stack on a
[Coolify](https://coolify.io) server with automatic HTTPS. It covers the
mandatory pre-deploy secret setup, the exact Coolify settings, and every issue
we hit getting it running (including the `:8080` domain suffix that trips
almost everyone up).

> Tested on Coolify v4 with Docker Compose resources. Replace
> `registry.example.com` with your own domain throughout.

## Architecture at a glance

```
Internet ──HTTPS──▶ Traefik (Coolify) ──:8080──▶ harbor-router
                                                    │
                          ┌─────────────────────────┴─────────────────────────┐
                          ▼                                                   ▼
                    harbor-portal (:8080)                             harbor-core (:8080)
                    static UI                                         API, /c, /service, /v2
                                                                            │
                     ┌──────────────┬──────────────┬───────────────────────┘
                     ▼              ▼              ▼
                  harbor-db      harbor-redis    registry ── registryctl
                  PostgreSQL     Valkey          blobs       garbage collection
                                                      ▲
                                               harbor-jobservice
```

- **`harbor-router`** is the only public service. It routes `/` to the portal
  and `/api`, `/c`, `/service`, `/v2` to core.
- **Coolify handles:** Traefik, TLS termination, Let's Encrypt certificates,
  Docker networking, container lifecycle.
- **You handle:** `/data/harbor` (configs, secrets, database, registry blobs)
  and the environment variables.

> Why a separate `docker-compose.coolify.yml`? Coolify's compose parser rejects
> variables inside volume definitions
> ([coollabsio/coolify#7127](https://github.com/coollabsio/coolify/issues/7127)).
> The Coolify variant uses literal `/data/harbor` paths instead of the
> `HARBOR_*_VOLUME` variables used by `docker-compose.yml`. It is generated by
> `scripts/render-coolify-compose.sh` (`make coolify-compose`).

## Prerequisites

- [ ] A server running Coolify (v4) with Docker.
- [ ] A domain/subdomain with an **A record** pointing at the server, e.g.
      `registry.example.com`.
- [ ] Ports **80** and **443** reachable (Let's Encrypt HTTP challenge).
- [ ] `git` and `openssl` on the server.
- [ ] This repository pushed to a Git remote Coolify can read.

# In Coolify ---------------------------------------------------------------

# 2. Docker Compose Location: docker-compose.coolify.yml

## Step 1 — Clone the repository on the VPS

```bash
sudo git clone https://github.com/ub360-ai/Self-Host-Docker-Images.git /opt/harbor
cd /opt/harbor
```

`/opt/harbor` is your working copy for the config files and the bootstrap
script. Coolify keeps its own clone in its application directory — that is
fine; the containers mount `/data/harbor`, not the repository.

## Step 2 — Prepare /data/harbor and generate secrets (mandatory)

**Do this before Coolify first parses the compose.** Coolify materializes every
bind-mount source on the server; if a **file** source does not exist yet, it
creates a **directory** at that path, and the deploy then fails with:

```
not a directory: Are you trying to mount a directory onto a file
```

```bash
cd /opt/harbor

# 1. config files (committed in the repo) -> /data/harbor/config
sudo mkdir -p /data/harbor/config
sudo cp -r config/. /data/harbor/config/
sudo chmod -R a+rX /data/harbor/config

# 2. environment file
cp .env.production.example .env.production
nano .env.production
#   EXTERNAL_URL=https://registry.example.com
#   PORTAL_URL=https://registry.example.com
#   everything else already points at /data/harbor

# 3. generate all secrets, keys and runtime directories
sudo ./scripts/gen-secrets.sh .env.production
```

`gen-secrets.sh` creates:

| Path | Purpose |
|---|---|
| `/data/harbor/database` | PostgreSQL data |
| `/data/harbor/redis` | Valkey data |
| `/data/harbor/registry` | registry blobs |
| `/data/harbor/job_logs` | jobservice logs |
| `/data/harbor/ca_download` | core CA downloads |
| `/data/harbor/secret/core/private_key.pem` | core token-signing key (RSA-4096) |
| `/data/harbor/secret/keys/secretkey` | core encryption key (16 chars) |
| `/data/harbor/secret/registry/passwd` | registry htpasswd (bcrypt) |
| `/data/harbor/secret/jobservice/config.yml` | rendered jobservice config |

It also fixes ownership (`999:999` for PostgreSQL/Valkey, `10000:10000` for
Harbor, secret files mode `600`).

**Verify the file mounts exist as files:**

```bash
for p in /data/harbor/config/portal/nginx.conf \
         /data/harbor/config/nginx/router.conf \
         /data/harbor/config/registry/config.yml \
         /data/harbor/config/registryctl/config.yml \
         /data/harbor/secret/core/private_key.pem \
         /data/harbor/secret/keys/secretkey \
         /data/harbor/secret/registry/passwd \
         /data/harbor/secret/jobservice/config.yml; do
  [ -f "$p" ] && echo "OK file: $p" || echo "MISSING/DIR: $p"
done
```

All eight must print `OK file`.

> **Keep `.env.production` and `/data/harbor/secret` off git.** The values are
> generated on the server; copy them into Coolify's Environment Variables in
> the next step.

## Step 3 — Create the Coolify resource

1. **New Resource → Git repository**, choose this repo.
2. Build Pack: **Docker Compose**.
3. **Docker Compose Location:** `docker-compose.coolify.yml`.
4. **Environment Variables:** paste every value from `/opt/harbor/.env.production`.
   - `EXTERNAL_URL` / `PORTAL_URL` = `https://registry.example.com`
   - `HARBOR_ADMIN_PASSWORD` = the generated admin password
   - all other generated secrets, limits, etc.
   - The `HARBOR_*_VOLUME` variables are **not referenced** by the Coolify
     compose, so Coolify will not ask for them.
5. You do **not** need *Preserve Repository During Deployment* — every mount is
   an absolute `/data/harbor` path.

## Step 4 — Set the domain on harbor-router (this is what gets you SSL)

In the resource's service list, set **Domains** for **`harbor-router` only**:

```
https://registry.example.com:8080
```

- The **`:8080` suffix is the internal container port**. Without it Coolify
  routes to port 80, where nothing listens, and the domain returns
  **502 Bad Gateway**.
- Coolify generates the Traefik labels and requests the Let's Encrypt
  certificate for `registry.example.com`.
- Leave the Domains fields for `harbor-db`, `harbor-redis`, `harbor-portal`,
  `harbor-core`, `registry`, `registryctl` and `harbor-jobservice` **empty** —
  they are internal-only.

Make sure `EXTERNAL_URL` and `PORTAL_URL` are the public URL **without** the
port (`https://registry.example.com`); Harbor derives redirects and the Docker
token realm from them.

## Step 5 — Deploy and verify

Deploy from Coolify, then:

```bash
# containers should all be healthy (Coolify prefixes container names)
docker ps --format '{{.Names}}\t{{.Status}}'

# portal (expect HTTP/2 200)
curl -sI https://registry.example.com/ | head -1

# core API (expect 200)
curl -s -o /dev/null -w '%{http_code}\n' https://registry.example.com/api/v2.0/ping

# Docker token realm (expect https://registry.example.com/service/token)
curl -sI https://registry.example.com/v2/ | grep -i www-authenticate
```

Push and pull an image through the domain:

```bash
echo "$HARBOR_ADMIN_PASSWORD" | docker login registry.example.com -u admin --password-stdin
docker tag alpine:3 registry.example.com/library/alpine:3
docker push registry.example.com/library/alpine:3
docker pull registry.example.com/library/alpine:3
```

## Step 6 — First login

- **Username:** `admin` (Harbor's built-in administrator, `user_id=1` — fixed
  and cannot be changed).
- **Password:** `HARBOR_ADMIN_PASSWORD` from your env file / Coolify.

`REGISTRY_USERNAME=registry` / `REGISTRY_PASSWORD` are the **internal**
`harbor-core` → `registry` credentials. They will never work in the portal.

## Troubleshooting

### `Invalid Docker volume definition: … forbidden character '${'`

Coolify rejects variables inside volume definitions. You are deploying the
wrong compose file — set **Docker Compose Location** to
`docker-compose.coolify.yml` (literal `/data/harbor` mounts). No Coolify update
is required.

### `not a directory: Are you trying to mount a directory onto a file`

Coolify created directories at file-mount paths because the files did not exist
before it parsed the compose. Fix:

```bash
# 1. remove the empty directories Coolify created (inspect first)
for p in \
  /data/harbor/config/portal/nginx.conf \
  /data/harbor/config/nginx/router.conf \
  /data/harbor/config/registry/config.yml \
  /data/harbor/config/registryctl/config.yml \
  /data/harbor/secret/core/private_key.pem \
  /data/harbor/secret/keys/secretkey \
  /data/harbor/secret/registry/passwd \
  /data/harbor/secret/jobservice/config.yml; do
    if [ -d "$p" ]; then ls -A "$p"; rmdir "$p" && echo "removed $p"; fi
done

# 2. run the Step 2 preparation, then redeploy
```

### `502 Bad Gateway` at the domain

The response has `alt-svc` and no `server: nginx` header → it comes from
Traefik, which cannot reach `harbor-router`.

1. **Most common:** the `harbor-router` domain is missing the `:8080` suffix.
   Set it to `https://registry.example.com:8080`.
2. Coolify's proxy is not on the stack network. Check:
   ```bash
   docker inspect <proxy-container>  -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
   docker inspect <router-container> -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
   ```
   If they differ, enable Coolify's **Connect To Predefined Network** for the
   resource, or set `HARBOR_NETWORK_NAME` to the network the proxy is on.
3. The proxy cannot reach the router at all:
   ```bash
   docker exec <proxy-container> wget -q -O /dev/null http://<router-ip>:8080/ && echo OK
   ```

### `504 Gateway Timeout` / intermittent 502

Intermittent failures with this in the router log:

```
connect() failed (111: Connection refused) while connecting to upstream,
upstream: "http://[fd0a:...]:8080/"
```

The router resolved an upstream to IPv6 while that service listened on IPv4
only. The configs in this repo already include `listen [::]:8080;` for the
portal and router. If you use an older checkout, update and re-apply:

```bash
cd /opt/harbor && git pull
cp config/portal/nginx.conf /data/harbor/config/portal/nginx.conf
cp config/nginx/router.conf /data/harbor/config/nginx/router.conf
docker restart <portal-container> <router-container>   # or redeploy in Coolify
```

Confirm both listen on IPv6:

```bash
docker exec <portal-container> netstat -tln | grep 8080   # expect 0.0.0.0 and [::]
```

### `incorrect login details`

Use `admin`, not `registry`, and the `HARBOR_ADMIN_PASSWORD` value. Harbor only
applies `HARBOR_ADMIN_PASSWORD` once, when the admin row has no password; later
env changes are ignored (core logs *"Admin password from config … ignored:
password already exists in database"*). This commonly happens if you pasted the
`__GENERATED_ADMIN_PASSWORD__` token into Coolify **before** running
`gen-secrets.sh`.

Reset it (keeps all data):

```bash
# 1. set HARBOR_ADMIN_PASSWORD in Coolify to the real generated value
# 2. clear the stored password so core re-applies the env value on next start
docker exec <db-container> psql -U postgres -d registry -c \
  "UPDATE harbor_user SET salt='', password='' WHERE user_id=1;"
# 3. restart/recreate core
docker restart <core-container>    # or redeploy in Coolify
# 4. confirm
docker logs --since 1m <core-container> 2>&1 | grep -i 'updated its encrypted password'
```

### Config changes don't take effect

Coolify mounts `/data/harbor/config/...`, not the repository. After changing a
config:

```bash
cd /opt/harbor && git pull
cp config/<file> /data/harbor/config/<file>
docker restart <affected-container>    # or redeploy in Coolify
```

### `docker restart harbor-portal` — no such container

Coolify prefixes container names (e.g.
`harbor-portal-<hash>-<hash>`). Get the exact names with:

```bash
docker ps --format '{{.Names}}' | grep -E 'portal|router|core|db'
```

## Operations

- **Update Harbor:** set `HARBOR_VERSION` in Coolify, redeploy. Core applies DB
  migrations on start.
- **Backups:** from `/opt/harbor`, `make db-backup` (consistent SQL dump) and
  `make backup` (archive of the data directory) write to `./backups`.
- **Rotate the admin password:** change it in the portal (Administration →
  Users), or use the reset procedure above.
- **Rotate inter-service secrets:** update the value in Coolify and recreate
  the affected services (`core`, `jobservice`, `registry`).
- **Regenerate keys:** `./scripts/gen-secrets.sh .env.production --force` — plan
  a maintenance window; regenerating the token key invalidates issued Docker
  tokens.

## Security notes

- Never commit `.env.production` or `/data/harbor/secret`; keep them readable
  only by root.
- Paste secrets only into Coolify's Environment Variables UI.
- Only `harbor-router` should be exposed; leave the other services without
  domains.
- Keep TLS on (Coolify/Let's Encrypt) and `EXTERNAL_URL` on HTTPS.
